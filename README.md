# zk-KYC

A working (not mocked) system for: real human liveness + live document presence verification → issuer signs
an age credential → holder proves "18+, validly signed, without revealing my
birthdate/photo/video" with a real PLONK zk-SNARK → proof verified locally or
on a public Ethereum testnet.

Every cryptographic and ML component listed below is a real library doing
real work. The places where "real" has an honest asterisk are called
out explicitly in **Scoping & honesty notes** — read that section before
relying on this for anything.

## 2. Setup

**System packages** (install via your OS package manager before `setup.sh`):
`git`, `curl`, `node >=18`, `python3` (+`venv`), `circom` (v2.1.6), `tesseract-ocr`,
`ffmpeg`. Optional: `espeak-ng` (lets the speech-liveness tests run),
`anvil` from [Foundry](https://getfoundry.sh) (lets the on-chain test run
locally instead of against Sepolia).

```bash
bash setup.sh
```

This is idempotent and fails loudly rather than skipping a step silently. It:
compiles both circuits, downloads the public Powers-of-Tau file, runs PLONK
setup and exports the Solidity verifier, generates an issuer EdDSA keypair,
builds a Python venv with all ML deps, clones Silent-Face-Anti-Spoofing,
downloads the Vosk speech model, and prints a capability report.

## 3. Running everything

### 3.1 Circuit + crypto tests (no server needed)
```bash
node --test test/circuit.test.js
```
Runs entirely against artifacts produced by `setup.sh` — no network, no
webcam, no ML models. ~7 tests, each proving one specific security property
(see §5).

### 3.2 On-chain tests
```bash
# local (auto-spawns anvil):
node --test test/onchain.test.js

# against real Sepolia (requires a funded key):
SEPOLIA_FUNDED_PRIVATE_KEY=0x... node --test test/onchain.test.js
```

### 3.3 Issuer service — automated tests
```bash
cd issuer-service
../.venv/bin/pytest -m "not hardware"
```
Starts a real Node EdDSA signer as a session-scoped fixture, then runs real
Silent-Face-Anti-Spoofing, real Tesseract OCR, and (if `espeak-ng`+Vosk are present)
real speech recognition against synthetic media generated by `tests/synth.py`.

### 3.4 Issuer service — running live
```bash
cd issuer-service
SIGNER_TOKEN=$(openssl rand -hex 24) bash -c '
  node ../issuer-service/signer/server.js &
  SIGNER_TOKEN=$SIGNER_TOKEN ../.venv/bin/uvicorn app.main:app --port 8000
'
```
(Run the signer and uvicorn as two processes sharing the same `SIGNER_TOKEN`;
the one-liner above is illustrative — in practice use two terminals.)

Check `GET /healthz` first — it tells you exactly which components are ready
and whether `issuance_possible` is true. The service fails closed: if
passive-liveness or the signer is unavailable, `/v1/sessions/{id}/submit`
returns `503`, it never silently skips a check.

### 3.5 Full hardware acceptance run (real human, real webcam)
```bash
python scripts/record_and_issue.py http://127.0.0.1:8000 /path/to/your/id_photo.jpg
```
or, as an automated pytest marker:
```bash
ENABLE_HARDWARE_TESTS=1 HW_ID_PHOTO_PATH=/path/to/id.jpg \
  ../.venv/bin/pytest -m hardware issuer-service/tests/test_hardware_e2e.py
```
This is **the** definitive test of the live human and document verification pipeline.

### 3.6 End-to-end: issue → prove → verify → submit on-chain
```bash
# 1. Get a real credential (interactive, needs webcam + your ID photo)
python scripts/record_and_issue.py http://127.0.0.1:8000 id_photo.jpg
#    -> writes /tmp/xxxx.credential.json and prints next steps

# 2. Anyone can check the issuer's signature independently
node scripts/verify-issuer-signature.js /tmp/xxxx.credential.json

# 3. Generate a zk proof of "18+, validly signed" (birthdate/photo NOT included)
node scripts/generate-proof.js /tmp/xxxx.credential.json -o proofs/mine.proof.json

# 4. Verify it locally
node scripts/verify-proof.js proofs/mine.proof.json

# 5. Deploy the verifier to Sepolia (prints a fresh wallet address to fund)
node scripts/deploy-verifier.js

# 6. Submit your proof on-chain; get a public Etherscan result
PRIVATE_KEY=0x... node scripts/submit-proof.js proofs/mine.proof.json
```

## 4. Architecture

**Trust model.** The issuer is a trust anchor: verifiers pin the issuer's
EdDSA public key (`keys/issuer.public.json`) out-of-band. The circuit proves
the credential was signed by *some* key holder over *this exact birthdate*;
it is the verifier's policy layer (`verify-proof.js` / `verifyBundle()`)
that additionally checks that key equals the pinned one. This split is
deliberate and tested explicitly (see "forged/self-signed credential" test):
cryptography alone cannot know who is trustworthy.

**Credential contents** — and nothing else, enforced structurally by
`credential_schema.py` and independently re-checked by
`verify-issuer-signature.js`:
```json
{
  "schema": "zkkyc-credential-v1",
  "issuer_id": "...", "issued_at": "...",
  "issuer_pub": {"ax": "...", "ay": "..."},
  "subject": {"dob": {"year": 1990, "month": 5, "day": 14}},
  "holder_secret": "...",
  "signature": {"R8x": "...", "R8y": "...", "S": "..."}
}
```
No photo, video, embedding, or biometric artifact of any kind is ever
written into a credential — the issuer discards all biometric and media data after
the pass/fail decision.

**Circuit.** `AgeCredential` (Circom 2, PLONK) proves in zero knowledge:
(1) `(birthYear+18, birthMonth, birthDay) <= refPacked` (a packed-date
comparison via `LessEqThan`), and (2) a valid EdDSA-Poseidon signature by
`(ax, ay)` over `Poseidon(year, month, day, secret)`. `ax`, `ay`, and
`refPacked` are public; birthdate and secret stay private. `refPacked` is a
public input the verifier's own policy pins to "now − 18 years" with a
±2‑day skew tolerance (`REF_DATE_STALE`), so a proof can't be replayed
against a stale cutoff.

**Issuer pipeline** (`issuer-service/app/main.py`), fail-closed at every
stage:
1. **Passive Liveness**: MiniFASNet ensemble via vendored Silent-Face-Anti-Spoofing on the live face clip.
2. **Active Liveness**: Response to *this session's* randomly chosen challenge (head-turn direction tracking or Vosk digit speech recognition).
3. **DOB Extraction**: High-resolution birthdate extraction from the uploaded ID photo via Tesseract OCR (`ocr_dob.py`).
4. **Document Presence**: Lightweight text-detection and confidence check on the live document video clip (`document_liveness.py`) to confirm a physical document was presented during the live session, with soft DOB corroboration logging.
5. **Signing**: EdDSA signing via a localhost-only Node signer over `Poseidon(dob, secret)`.

Sessions are one-shot (`SessionStore.consume`) so a submission can never be replayed.

**On-chain.** `PlonkVerifier.sol` is generated verbatim by
`snarkjs zkey export solidityverifier` — not hand-written — from the same
proving key used off-chain. `ProofRegistry.sol` is a 15-line wrapper that
does nothing cryptographic; it just emits an event so a verification result
is publicly visible on Etherscan.

## 5. What each automated test proves

| Test | Property |
|---|---|
| `circuit.test.js`: valid adult | prove+verify succeeds end to end |
| `circuit.test.js`: underage | witness generation fails at the constraint level — a false age claim cannot even produce a proof |
| `circuit.test.js`: tampered proof bytes | mutated proof fails verification |
| `circuit.test.js`: wrong VK | a proof for a different circuit (different R1CS) is rejected, both by policy and by raw `snarkjs plonk verify` |
| `circuit.test.js`: forged/self-signed | proof is mathematically valid (expected — the signature really is valid for the attacker's own key) but is **rejected by the trust-anchor policy check**, `ISSUER_KEY_MISMATCH` |
| `circuit.test.js`: signature over wrong message | witness generation fails — the signed message commits to the exact birthdate, so credentials can't be "re-dated" |
| `circuit.test.js`: tampered public inputs | mutated `refPacked` breaks raw SNARK verification |
| `circuit.test.js`: stale cutoff | freshness policy rejects a proof presented against an out-of-date cutoff |
| `onchain.test.js` | the identical compiled verifier bytecode accepts a valid proof and reverts on a tampered one, on a real EVM (anvil or Sepolia); result is logged in a public event |
| `test_passive_liveness.py`: flat/print-style image | real MiniFASNet ensemble classifies it as an attack |
| `test_passive_liveness.py`: vendor missing | constructor raises, and the API layer (`test_sessions_api.py`) confirms this produces an HTTP 503 refusal, never a silent pass |
| `test_active_liveness.py` | correct head-turn direction passes; wrong direction, no motion, wrong digit order, and unrelated audio all fail |
| `test_document_liveness.py` | live document frames containing text pass document presence; face-only frames (user forgot to present ID) and noisy frames fail; soft corroboration logs DOB matches without hard-rejecting |
| `test_ocr.py` | DOB is extracted exactly from rendered ID cards across multiple formats/seeds; absent or implausible dates raise rather than guessing |
| `test_sessions_api.py` | sessions expire, sessions are one-shot (replay fails), and issuance is refused (503) with the passive model disabled |
| `test_crypto_e2e.py` | full chain: Node signer issues → third-party signature check → real snarkjs PLONK proof → real verification; underage credential cannot produce a witness |
| `test_hardware_e2e.py` | (opt-in, `ENABLE_HARDWARE_TESTS=1`) a real human passes the *entire* two-phase pipeline live |

## 6. Scoping & honesty notes

### 6.1 What this system verifies — and what it explicitly does NOT verify

This system enforces identity verification through a document-liveness and OCR-corroboration model:
- **What is verified:**
  1. **A real, live human was present** interacting with the system (verified via MiniFASNet passive anti-spoofing and dynamic active challenges: head turn / spoken digits).
  2. **A physical document was displayed** in the same live session (confirmed via lightweight OCR text detection on the live document video clip).
  3. **A valid Date of Birth was extracted** from a separately uploaded clear, high-resolution photo of the document.
- **What is NOT verified (Deliberate Design Decisions & Scope Limits):**
  1. **Does NOT verify that the live human is the person pictured on the document:**
     Real-photo testing demonstrated that DeepFace comparison against printed or scanned ID photos consistently produces cosine distances of $0.75\text{--}0.79$ against live webcam feeds — regardless of face alignment (MTCNN), detector backend, or super-resolution preprocessing (FSRCNN/EDSR 2x/4x). This physical-to-digital domain gap cannot be fixed by threshold tuning without rendering the threshold meaningless. The issuance pipeline therefore explicitly omits 1:1 facial biometric matching.
  2. **Document-presence detection confirms "a text-bearing object was shown to the camera," NOT "a valid government ID was shown":**
     The document presence stage confirms that a physical document containing legible text was presented in the live camera feed. It does **not** perform forensic document authenticity validation (such as UV holograms, MRZ checksums, NFC chip cryptographic verification, or government database cross-checks).

---

### 6.2 Other Scoping & Honesty Notes

- **Biometric test media is synthetic, and that has a real, structural limit:** `tests/synth.py` renders deterministic procedural faces with OpenCV/PIL — genuinely different pixels per identity/pose, enough to exercise OCR and document presence meaningfully, and enough that a *flattened* render (`render_flat_photo`) reliably triggers the real anti-spoofing model's attack classifier (`test_printed_photo_style_attack_rejected`). What synthetic media **cannot** honestly demonstrate is genuine-class acceptance by the passive-liveness model, because a rendered face and a printed photo/screen-replay are the same category of thing from a 3-D-cue standpoint.
- **On-chain deployment needs your funding action, by design:** `deploy-verifier.js` generates a fresh throwaway wallet, prints its address, and blocks until it sees ≥0.02 Sepolia ETH. Once funded, deployment and submission are fully automated.
- **Trusted setup uses a public, reused ceremony file, not a bespoke one — verify its provenance yourself:** `setup.sh` downloads `powersOfTau28_hez_final_15.ptau` from public mirrors and prints its SHA-256. Cross-check the printed digest against the Perpetual Powers of Tau transcript before treating a deployment as production-grade.
- **No credential revocation:** Once issued, a credential/proof is valid until an underlying key or policy changes.
- **Issuer key compromise breaks the whole trust anchor:** The signer binds to `127.0.0.1` and requires a constant-time-compared bearer token, but there is no HSM or multi-party issuance in this delivery.
- **`verify-proof.js` freshness window (±2 days)** is a policy choice, not a cryptographic guarantee; a verifier can choose a different window via `--max-skew-days`.
- **Rate limiting (`RATE_LIMIT_PER_HOUR`) is in-memory and per-process.**
