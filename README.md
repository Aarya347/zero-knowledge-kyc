# zero-knowledge-kyc

A zero-knowledge identity verification (KYC) system: prove age eligibility
using a real zero-knowledge proof — without revealing a birthdate, face,
ID photo, or video to anyone who checks the proof.

This is not a demo or a mockup. Every cryptographic and ML component is a
real library doing real work: a real Circom/PLONK circuit, real EdDSA
signatures, real anti-spoofing and OCR models, and a real Solidity verifier
deployable on a public Ethereum testnet. It has been tested against real
hardware (a real webcam, a real government-issued ID, a real human) — not
just synthetic fixtures — and that testing surfaced and fixed a genuine
correctness bug along the way (§7.1). Read **§6 (Scoping & honesty notes)**
before relying on this for anything beyond learning/experimentation.

---

## 1. What this actually proves, in one paragraph

A person completes a one-time live verification session: they perform a
liveness challenge (head-turn or spoken digits) in front of a webcam, then
hold up their physical ID to the same camera, and separately upload a clear
photo of that ID. If a real live human was present, a document was shown,
and a birthdate was extracted from the clean photo, the issuer signs a
credential over that birthdate. From then on, the holder can generate a
fresh zero-knowledge proof — locally, or verified publicly on-chain — that
says "this credential holder meets the age requirement, signed by a
trusted issuer" without ever revealing the birthdate itself, and without
the holder ever handing their ID or face to whoever is checking.

## 3. Setup

**System packages** (install via your OS package manager before `setup.sh`):
`git`, `curl`, `node >=18`, `python3` (+`venv`), `circom` (v2.1.6),
`tesseract-ocr`, `ffmpeg`. Optional: `espeak-ng` (lets the speech-liveness
tests run — currently not installed in the dev environment this was built
in, see §7.3), `anvil` from [Foundry](https://getfoundry.sh) (lets the
on-chain test run locally instead of against Sepolia).

```bash
bash setup.sh
```

Idempotent, fails loudly rather than skipping a step silently. Compiles
both circuits, downloads the public Powers-of-Tau file, runs PLONK setup
and exports the Solidity verifier, generates an issuer EdDSA keypair,
builds a Python venv with all ML deps, clones Silent-Face-Anti-Spoofing,
downloads the Vosk speech model, and prints a capability report.

## 4. Running everything

### 4.1 Circuit + crypto tests (no server needed)

```bash
node --test test/circuit.test.js
```

Runs entirely against artifacts produced by `setup.sh` — no network, no
webcam, no ML models. 11 tests (see §5).

### 4.2 On-chain tests

```bash
# local (auto-spawns anvil):
node --test test/onchain.test.js

# against real Sepolia (requires a funded key):
SEPOLIA_FUNDED_PRIVATE_KEY=0x... node --test test/onchain.test.js
```

### 4.3 Issuer service — automated tests

```bash
cd issuer-service
../.venv/bin/pytest -m "not hardware"
```

Starts a real Node EdDSA signer as a fixture, then runs real
Silent-Face-Anti-Spoofing, real Tesseract OCR, and (if `espeak-ng`+Vosk are
present) real speech recognition against synthetic media
(`tests/synth.py`).

### 4.4 Issuer service — running live

```bash
cd issuer-service
SIGNER_TOKEN=$(openssl rand -hex 24) node ../issuer-service/signer/server.js &
SIGNER_TOKEN=$SIGNER_TOKEN ../.venv/bin/uvicorn app.main:app --port 8000
```

(Run the signer and uvicorn as two processes sharing the same
`SIGNER_TOKEN` — use two terminals in practice.)

Check `GET /healthz` first — it reports exactly which components are ready
and whether `issuance_possible` is true. The service fails closed: if
passive-liveness or the signer is unavailable, submission returns `503`,
never a silent skip.

### 4.5 Web UI (recommended way to actually try this)

```bash
# Terminal 1
SIGNER_TOKEN=test_secret_token_12345 node issuer-service/signer/server.js

# Terminal 2
cd issuer-service
SIGNER_TOKEN=test_secret_token_12345 ../.venv/bin/uvicorn app.main:app --port 8000 --reload

# Terminal 3
cd web
npm install
npm run dev
```

Open `http://localhost:5173`. Guides you through: health check → liveness
challenge → document-presence clip → ID photo upload → issued credential
(with a readable summary, collapsed technical/cryptographic details, and
in-UI "Generate Proof" / "Verify Proof" buttons — no terminal required
past this point).

### 4.6 Full hardware acceptance run (real human, real webcam)

```bash
python scripts/record_and_issue.py http://127.0.0.1:8000 /path/to/your/id_photo.jpg
```

or:

```bash
ENABLE_HARDWARE_TESTS=1 HW_ID_PHOTO_PATH=/path/to/id.jpg \
  ../.venv/bin/pytest -m hardware issuer-service/tests/test_hardware_e2e.py
```

This is **the** definitive test of the live-human and document-presence
pipeline — the only thing that actually exercises it against real biometric
signal instead of synthetic renders.

### 4.7 End-to-end CLI: issue → prove → verify → submit on-chain

```bash
# 1. Get a real credential (needs webcam + your ID)
python scripts/record_and_issue.py http://127.0.0.1:8000 id_photo.jpg

# 2. Anyone can check the issuer's signature independently
node scripts/verify-issuer-signature.js credential.json

# 3. Generate a zk proof of age eligibility (birthdate is NOT included)
node scripts/generate-proof.js credential.json -o proofs/mine.proof.json

# 4. Verify it locally
node scripts/verify-proof.js proofs/mine.proof.json

# 5. Deploy the verifier to Sepolia (prints a fresh wallet address to fund
#    from a free faucet — testnet ETH, no real money involved)
node scripts/deploy-verifier.js

# 6. Submit your proof on-chain; get a public Etherscan result
PRIVATE_KEY=0x... node scripts/submit-proof.js proofs/mine.proof.json
```

(All of this is also available via buttons in the web UI, except step 5-6.)

## 5. What each automated test proves

| Test | Property |
|---|---|
| `circuit.test.js`: valid adult | prove+verify succeeds end to end |
| `circuit.test.js`: underage | witness generation fails at the constraint level — a false age claim cannot even produce a proof |
| `circuit.test.js`: tampered proof bytes | mutated proof fails verification |
| `circuit.test.js`: wrong VK | a proof for a different circuit is rejected, both by policy and raw `snarkjs plonk verify` |
| `circuit.test.js`: forged/self-signed | proof is mathematically valid (expected) but **rejected by the trust-anchor policy check** |
| `circuit.test.js`: signature over wrong message | witness generation fails — signed message commits to the exact birthdate |
| `circuit.test.js`: tampered public inputs | mutated `refPacked` breaks raw SNARK verification |
| `circuit.test.js`: stale cutoff | freshness policy rejects a proof against an out-of-date cutoff |
| `circuit.test.js`: real 20-year-old / real 17-year-old | regression tests added after the age-offset bug (§7.1) — confirm ages 18-35 pass and under-18 fails, not just the one coincidental age that worked before |
| `onchain.test.js` | identical compiled verifier bytecode accepts a valid proof and reverts on a tampered one, on a real EVM |
| `test_passive_liveness.py` | real MiniFASNet ensemble classifies a flat/print-style image as an attack; fails closed if the vendor model is missing |
| `test_active_liveness.py` | correct head-turn/digits pass; wrong direction, no motion, wrong order, unrelated audio all fail |
| `test_document_liveness.py` | live document frames with text pass; face-only frames (user forgot to show ID) and noisy frames fail; soft DOB corroboration logs without hard-rejecting |
| `test_ocr.py` | DOB extracted exactly from rendered ID cards; absent/implausible dates raise rather than guess |
| `test_sessions_api.py` | sessions expire, are one-shot (replay fails), and issuance is refused (503) with a missing model |
| `test_crypto_e2e.py` | full chain: signer issues → signature check → real PLONK proof → real verification (currently broken, see §7.3) |
| `test_hardware_e2e.py` | (opt-in) a real human passes the entire two-phase pipeline live — this is what actually validated the system tonight |

## 6. Scoping & honesty notes

### 6.1 What this system verifies — and what it explicitly does not

- **Verified:**
  1. A real, live human was present (MiniFASNet passive anti-spoofing + a
     dynamic active challenge).
  2. A physical document was displayed during that same live session
     (live OCR text-presence check).
  3. A valid date of birth was extracted from a separately uploaded, clear,
     high-resolution photo of that document.
- **NOT verified — deliberate scope limits, not oversights:**
  1. **That the live human is the person pictured on the document.**
     Real-photo testing showed DeepFace comparison against printed/scanned
     ID photos consistently lands at cosine distance 0.75–0.79 against
     live webcam frames — regardless of face alignment, detector backend,
     or 2x/4x super-resolution preprocessing, all tested and ruled out.
     This is a domain gap (printed/scanned photo vs. live camera capture),
     not a threshold-tuning problem — see the archived investigation in
     `archive/face_matching/README.md` for the full numbers. 1:1 face
     biometric matching was removed rather than shipped with a threshold
     loose enough to be meaningless.
  2. **That the document shown is a valid, authentic government ID.**
     Document-presence detection confirms "a text-bearing object was shown
     to the camera" — it does not check document type, holograms, MRZ
     checksums, or any government database.
  3. **That the ID shown belongs to the person holding it.** Nothing in
     this system currently prevents someone from presenting a real ID that
     isn't theirs — see §7.4.

### 6.2 Other scoping notes

- **Synthetic test media has a real, structural limit.** `tests/synth.py`
  renders procedural OpenCV/PIL faces — enough to exercise OCR and
  document-presence meaningfully, and enough that a flattened render
  reliably triggers real anti-spoofing attack-classification. What it
  **cannot** honestly demonstrate is genuine-class face/liveness acceptance,
  because a procedural render and a printed-photo spoof are the same
  category of thing from a 3D-cue standpoint. `test_hardware_e2e.py` is the
  only test that closes this gap.
- **On-chain deployment needs your funding action, by design.**
  `deploy-verifier.js` generates a fresh wallet, prints its address, and
  blocks until it sees ≥0.02 Sepolia ETH from a free faucet. Testnet ETH
  only — no real money involved anywhere in this project.
- **Trusted setup uses a public, reused ceremony file.** `setup.sh`
  downloads `powersOfTau28_hez_final_15.ptau` and prints its SHA-256 —
  cross-check that digest against the Perpetual Powers of Tau transcript
  yourself before treating a deployment as production-grade.
- **No credential revocation.** Once issued, valid until the underlying
  key or policy changes.
- **Issuer key compromise breaks the whole trust anchor.** The signer is
  localhost-only with a token, but there's no HSM or multi-party issuance.
- **The ±2-day freshness window** is a policy choice, adjustable via
  `--max-skew-days`, not a cryptographic guarantee.
- **Rate limiting is in-memory and per-process** — resets on restart, no
  shared store for horizontal scaling.

## 7. Where this stands right now

This project has been built and then genuinely stress-tested against real
hardware — not just a synthetic test suite — and that testing surfaced real
problems that got fixed or honestly scoped around, rather than papered
over. Here's the current state, plainly:

### 7.1 A real bug was found and fixed: the age check was enforcing eligibility wrong

Early versions of this system applied an 18-year offset **twice** — once
inside the circuit, once in the JS helper computing today's cutoff date —
which meant the system was actually enforcing **age ≥ 36**, not ≥ 18. This
went undetected through the entire synthetic test suite because every test
credential happened to use a DOB that made the test subject exactly 36
years old — a coincidence, not a correct test. It was only caught when a
real credential, for a real 20-year-old, was run through the full pipeline
and failed proof generation. Fixed in `scripts/lib/util.js`; regression
tests for both a real 20-year-old (passes) and a 17-year-old (correctly
fails) were added to `circuit.test.js` to make sure this specific class of
bug can't silently reappear.

**Takeaway:** the synthetic test suite alone was not sufficient to catch
this. Real end-to-end testing with varied, real data is what found it.

### 7.2 Face-matching was tried, tested, and deliberately removed

The original design included 1:1 biometric face-matching (live webcam face
vs. ID photo, via DeepFace). Real-hardware testing showed this doesn't
work reliably against printed/scanned ID photos — the comparison distance
sat at 0.75-0.79 regardless of alignment, detector backend, or
super-resolution preprocessing (all tried, all documented in
`archive/face_matching/`). Rather than loosen the match threshold to the
point of meaninglessness, or add a manual-review fallback, the system was
redesigned around **live document-presence** instead: proving a document
was shown live during the session, without claiming to verify whose face
is on it. This is a real, deliberate reduction in what the system claims —
documented in §6.1, not hidden.

### 7.3 Known open items

- `test_crypto_e2e.py` fails with a Python/Node import error — it tries to
  import the Node `scripts/lib` module from Python, which doesn't work as
  written. The supported path (proof generation via the Node CLI, or the
  web UI's buttons) works fine; this specific test needs its
  proof-generation step rewritten to shell out to Node rather than
  attempting a cross-language import.
- `test_active_liveness.py::test_correct_left_turn_passes` and the
  speech-challenge tests are skipped/inconclusive against synthetic media
  (expected — see §6.2) and have only been validated via the real hardware
  test.
- `espeak-ng` was not installed in the environment this was built in, so
  speech-liveness tests are currently skipped rather than run.
- Sepolia deployment has been tested against local `anvil` but not yet
  actually run against public Sepolia with a funded wallet.

### 7.4 Natural next steps, roughly in order of effort

1. **Deploy to Sepolia for real** — low effort, mostly following §4.7
   steps 5-6, gives a genuine public on-chain verification result.
2. **Fix `test_crypto_e2e.py`'s import**, and install `espeak-ng` so the
   speech-liveness tests actually run instead of skipping.
3. **Build a "prove my age" integration layer** — right now, using a
   proof against a third-party website requires manually running CLI
   commands or the local web UI; there's no browser-extension/wallet-style
   component a real website could actually integrate against, and no
   demo "relying party" website exists yet to test the full
   issuer→holder→verifier loop end to end.
4. **Address the "whose ID is this" gap (§6.1.3)** — if stronger identity
   binding is ever needed again, the honest options are: a
   cross-domain-trained face-verification model (a real research
   undertaking, not a config change), NFC/chip-based photo sources for
   documents that support them, or integrating a government digital-ID
   API (e.g. India's DigiLocker) so the reference photo is digital-native
   rather than printed-then-scanned.
5. **Credential revocation** — currently nonexistent; would need real
   design work (a revocation list the circuit checks, or short-lived
   credentials).
